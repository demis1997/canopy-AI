# Conversation response quality

The teasing loop has application-level causes. `compose.ts` previously instructed FLIRTY turns to use “light teasing” and EXPLICIT turns to “tease specifically.” The shared agency rules imposed a closer and required teasing before offers. Retrieval could inject scripts requiring escalation, questions, or delayed aftercare, regardless of the configured persona. In `validate-output.ts`, a tease request unconditionally replaced model candidates with a fixed pool; repeat, reveal, and rapport recovery could then replace them with another canned pool. No candidate ranking considered the last ten assistant messages. Existing flow memory tracks intake and product sequences rather than romantic progression. These findings do not establish a fault in Qwen itself.

The production path now keeps romantic progression separately from intake and the commercial funnel. State lives in creator/fan note `extra`, under a conversation-specific key, without a database migration. It stores the last input message IDs so rewrites and corrective retries do not count as new interest. Existing sent history bootstraps threads without stored state. Consecutive pending fan messages count as one turn. Clear romantic or intimate interest advances the conversational tone; hesitation resets it, and ordinary chat never escalates on a timer. Purchases and meaningful interactions can enter aftercare. Progression is evidence of conversational interest, not consent or a promised relationship.

The shared prompt used by the Qwen-compatible providers now prioritizes the configured persona, direct answers, non-graphic romance, factual representation and optional purchases. Legacy agency and intake scripts are omitted from the system prompt. Production retrieval excludes incompatible scripts and graphic examples. Creator boundaries and authorised facts remain in persona context. Prohibited words also receive a deterministic candidate check. Free-form boundaries still depend on the model following those instructions and on existing human review; they are not interpreted by a general semantic policy classifier.

Candidates are scored individually before product validation and after response guards. Checks cover the last ten CREATOR/CHATTER messages, near duplicates, repeated rhetorical questions, recurring deflections, emoji saturation, superficial answers to interest, consent pacing, prohibited persona words, graphic vocabulary and unsupported live-content claims. Existing grounding checks participate in candidate selection. Low-scoring options are removed; the strongest remaining option comes first. Production guards request a contextual retry instead of inserting stock reply pools. If a corrective generation still fails, no sendable option is returned and human review is required. These checks are deterministic heuristics, not a claim to measure full semantic relevance or catch every unsafe paraphrase.

Generation diagnostics and `SUGGESTIONS_PRODUCED` analytics metadata contain progression, scored candidates, and quality snapshots. Repetition and deflection rates describe actual recent assistant messages. Relevance is a heuristic pass rate. Engagement is fan messages per assistant message in the recent assistant window. Conversion records distinct presented products and distinct purchased products among those offers, with a nullable ratio when no offers exist. These are observed counts, not causal attribution or a forecast; conversions become visible on subsequent generations. Snapshot events should not be summed as unique purchases.

Age/consent prechecks, post-generation safety checks (including retries), tenant/product/price validation, stale-input detection, operator corrections, persisted approval requirements, reply selection, and automation send gates remain in place. No UI or send-policy changes are required. Legacy guard callers retain their compatibility behavior; the production generation path opts into contextual recovery.

Validation: shared progression simulations, AI prompt/retrieval/ranking tests, and mocked production pipeline tests cover progression, repeated interest, hesitation, ten-message history, persona injection, candidate selection, corrective generation, exhausted retries and age blocking. Existing approval and automation regression suites also run. Live Qwen inference and database/platform integration require their configured services and are not covered by the deterministic tests.
